# Browser integration tests

The signup-to-Gemini tests use a dedicated Auth0 test tenant and the real
Gemini API. They do not mock the provider response.

1. Configure `frontend/.env.local` with the app's Auth0 and Gemini settings.
2. Set `E2E_AUTH0_EMAIL` and `E2E_AUTH0_PASSWORD` in the shell to an existing,
   verified test user in that Auth0 tenant. Keep these credentials out of git.
3. Install the browser once with `npx playwright install chromium`.
4. Run `npm run test:e2e` from `frontend`.

The signup test verifies the app builds an Auth0 authorization redirect with
`screen_hint=signup`. The full assessment test signs in as the dedicated test
user, completes all applicable questionnaire sections, and requires the UI to show the
`Generated by Gemini` marker. That assertion fails if the API falls back to its
deterministic question, so a real provider response is required.

In the Auth0 application's settings, allow `http://localhost:3000/auth/callback`
as a callback URL, `http://localhost:3000` as a logout URL and web origin, and
set `APP_BASE_URL=http://localhost:3000` for local runs.

Auth0 email verification, connection settings, rate limits, and Gemini API
availability are external prerequisites. Use a disposable test tenant/account;
the test intentionally does not create or delete Auth0 users.
